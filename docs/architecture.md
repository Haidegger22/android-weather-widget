# Как устроено приложение

Документ описывает, из чего состоит проект и как связаны части. Источник истины — код в `app/src`.

## Состав

```
app/
├── AndroidManifest.xml        — разрешения, активности, виджет, <queries> для часов
├── res/
│   ├── layout/
│   │   ├── widget.xml             — разметка виджета 5×1 (часы + погода)
│   │   ├── activity_detail.xml    — подробное окно: шапка, лента часов, дни с графиком
│   │   ├── activity_city.xml      — поиск и список городов
│   │   ├── col_hour.xml           — колонка почасовой ленты
│   │   ├── col_day.xml            — колонка дня
│   │   └── row_city.xml           — строка результата поиска города
│   ├── drawable/                  — векторные иконки погоды (солнце, луна, облако, дождь, снег, туман, гроза, восход/закат) и стрелка обновления
│   ├── mipmap-*/                  — значки приложения (обычные) и передний план адаптивной иконки
│   ├── mipmap-anydpi-v26/         — адаптивная иконка для Android 8+
│   ├── values/                    — строки (в том числе название приложения), цвета, цвета фона иконки
│   └── xml/widget_info.xml        — параметры виджета: 5×1, обновление раз в 30 минут
└── src/com/ivanhoe/weather/
    ├── WeatherWidget.java         — сам виджет
    ├── DetailActivity.java        — подробное окно
    ├── CityActivity.java          — выбор города
    ├── OpenMeteoService.java      — загрузка и разбор прогноза, кэш
    ├── Prefs.java                 — сохранение города и последнего прогноза
    ├── Weather.java               — модель данных, описания и подбор иконок
    └── TempGraphView.java         — график максимумов и минимумов по дням (под точками даты `04.10`)
```

## Как работает виджет

| Шаг | Что происходит |
|---|---|
| Первое добавление и каждые 30 минут | `WeatherWidget.onUpdate` рисует виджет из кэша и запускает фоновое обновление |
| Обновление | отдельный поток (`goAsync`, чтобы система не убила приёмник) забирает прогноз и перерисовывает виджет |
| Часы | `TextClock` внутри `RemoteViews` — тикает сам, будильники и службы не нужны |
| Тап по времени | `PendingIntent` на часы системы: приложение ищет их среди установленных (имя пакета, класс, подпись), затем пробует системный интент «показать будильники» |
| Тап по погоде | `PendingIntent` на `DetailActivity` |
| Тап по дате или стрелке | широковещательный интент `ACTION_REFRESH` — обновление по требованию |

Важная деталь: в `AndroidManifest.xml` объявлен `<queries>` c `SHOW_ALARMS`, `SET_ALARM`,
`SHOW_TIMERS` и «главная активность лаунчера». Без этого на Android 11+ приложение не видит
чужие программы и «не находит» часы.

## Откуда берутся данные

Прогноз: `https://api.open-meteo.com/v1/forecast`

| Что берём | Поле API | Где используется |
|---|---|---|
| Текущая температура | `current.temperature_2m` | виджет и шапка подробного окна |
| Ощущается как | `current.apparent_temperature` | строка деталей |
| Влажность, ветер | `current.relative_humidity_2m`, `current.wind_speed_10m` | строка деталей |
| Код погоды и день/ночь | `current.weather_code`, `current.is_day` | иконка (солнце или луна) и описание |
| Почасовой прогноз | `hourly.temperature_2m`, `hourly.weather_code` (168 значений) | лента часов |
| Дни | `daily.temperature_2m_max/min`, `daily.weather_code` (7 дней) | колонки дней и график |
| Восход и закат | `daily.sunrise`, `daily.sunset` | отдельные точки в ленте часов |

Справочник городов: `https://geocoding-api.open-meteo.com/v1/search` с фильтром `countryCode=RU`
и `language=ru` — поиск работает с трёх букв, в ответе город и регион.

Кэш: последний ответ целиком сохраняется в настройках приложения, поэтому без сети показываются
последние данные, а не пустой виджет.

## Подбор иконок погоды

Коды погоды WMO (0 — ясно, 2 — переменная облачность, 3 — пасмурно, 45/48 — туман, 51–67 — морось
и дождь, 71–86 — снег, 95–99 — гроза) превращаются в векторные иконки. Для ясной и переменной
облачности учитывается `is_day`: ночью показывается луна, днём солнце. В почасовой ленте день и
ночь определяются по часу (с 6:00 до 21:00 — дневные иконки) — при желании легко заменить на
реальные восход и закат, которые уже приходят в прогнозе.

## График температур: две линии и даты под точками

Под колонками дней в подробном окне рисуется график на `Canvas` (класс `TempGraphView`): верхняя линия — дневной максимум, нижняя — ночной минимум, одно деление по горизонтали равно одному дню.

Правила отрисовки, к которым пришли после разбора жалобы «непонятно, что показывается на графике»:

- **Даты под точками в формате `04.10`** (`dd.MM`), дата сегодняшнего дня — светлее остальных. Без дат ось времени читается наугад: график идёт слева направо (от сегодня к седьмому дню), но без подписей его легко принять за перевёрнутый.
- **Подписи не пересекают линии:** максимум — всегда выше своей точки, минимум — всегда ниже своей; положение ограничено рамками вида (`Math.max` / `Math.min` от края). Иначе верхняя цифра уходит за верхний край, а нижняя наезжает на строку дат и читается как подпись соседней точки.
- **Запас по вертикали:** шкала растягивается на 25 % от реального разброса сверху и снизу, `padBottom` — 46 dp под строку дат, высота вида — 176 dp. Если вид низкий, датам просто негде разместиться.
- **Тот же формат в колонках дней** (`DetailActivity`, `dateFmt` = `dd.MM`): пользователь просит точку, а не слэш — `04.10`, а не `4/10`.

## Что можно менять без переделки

- **Название приложения** — `res/values/strings.xml`, ключ `app_name`.
- **Город по умолчанию** — `Prefs.DEFAULT_CITY`, `DEFAULT_LAT`, `DEFAULT_LON`.
- **Размер и период обновления виджета** — `res/xml/widget_info.xml`.
- **Часы дня для ленты** — константы в `DetailActivity`.
- **Источник данных** — класс `OpenMeteoService`: заменить адрес и разбор ответа.
